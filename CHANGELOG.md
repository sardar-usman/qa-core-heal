# Changelog

## 0.5.0 (2026-10-28)

Playwright JS/TS is now one adapter behind a shared core. Contract version 1 is unchanged. The JSON Schemas in `schemas/` are the same bytes as 0.4.0. This version runs Playwright only.

- **Added:** `--framework <id>` selects the adapter. Accepted values are `playwright-js`, `cypress-js`, `selenium-js`, `playwright-py`, and `selenium-py`. Only `playwright-js` runs. The other ids are recognised and refused with exit code 2, and nothing is written.
- **Added:** Framework detection. A findings `project.configPath`, then project marker files. Two matches are refused until you pass `--framework`. No match uses `playwright-js` and prints nothing. `--verbose` prints one line.
- **Added:** `capabilities` reports `features.frameworks` and `frameworkVersions`. `frameworkVersions["playwright-js"]` is the same value as `playwrightVersion`. Existing keys are unchanged.
- **Changed:** A project that has both a Playwright config and another framework's markers now needs `--framework playwright-js`.
- **Fixed:** The Chromium temp sweep removes new `.org.chromium.Chromium.*` files and folders. Entries that were already there, and entries a live process is using, stay. Without `/proc` the sweep removes nothing.
- **Fixed:** Without `/proc`, heal reads `ps` once per stop loop and answers every pid from that table.
- **Fixed:** In `--test` mode, a re-run that hits the run timeout is reported as a timeout and the heal is reverted.
- **Fixed:** In findings mode, a finding that never started because the run timeout was already used up gets its own message. The refusal code stays `timeout`.
- **Fixed:** A spec path that is absolute, or that contains `..`, is refused as outside the project, even when the resolved file would sit inside the project. The code stays `spec-not-found`. A missing relative path inside the project says it was not found.
- **Fixed:** If the spec was deleted after heal wrote it, the audit warning says so. The audit field names are unchanged.
- **Internal:** Playwright-specific parsing, reports, config loading, and the test runner live in the Playwright adapter. The registry contains `playwright-js` only.

## 0.4.2 (2026-10-28)

Hardening fixes from the 0.4.1 review. Contract version 1 is unchanged. The JSON Schemas in `schemas/` are the same bytes as 0.4.0. No CLI flag, exit code, or JSON field was removed or renamed. `features.runTimeout` stays true.

- **Fixed:** When a Playwright config does not set `testDir`, heal looks in the folder of the config file. That is Playwright's own default.
- **Fixed:** After a killed child run, heal removes `.org.chromium.Chromium.*` folders in the system temp directory that were created after that child started. Folders that were already there are left alone.
- **Fixed:** An explicit `--playwright-config` value that heal refuses fails the run with a clear error and exit code 1. A findings `configPath` that is refused is still ignored, and `--verbose` still says why.
- **Fixed:** On SIGINT, SIGTERM, or SIGHUP during `--apply` verification, heal restores the spec only when the file still contains exactly what heal wrote. If the file changed, heal leaves it and the audit entry includes a warning.
- **Fixed:** A Playwright child is dropped from the tracked process groups when it exits. The final SIGKILL reads the process table again, so a process that started after the first snapshot is included. Groups that are already dead are not signaled.
- **Fixed:** SIGHUP is trapped the same way as SIGINT and SIGTERM. The exit code is 129.
- **Changed:** `--run-timeout` is one time budget for every Playwright run in one heal command. In findings mode the default is now 10 minutes for the whole command. In 0.4.1 it was 10 minutes for each Playwright run. A long findings run that finished before may now stop with a `timeout` refusal. Raise the limit with `--run-timeout`.
- **Fixed:** A findings spec that is outside the project, and a symlink that points outside the project, are still refused with `spec-not-found`. The message says which of those it is.
- **Fixed:** The weakening guard refuses a change from `expect(...)` to `expect.soft(...)` or `expect.poll(...)`. It counts `test.fixme` and `test.describe.fixme` as skips. A regex literal no longer hides a later assertion, and an `expect` inside a template `${}` expression is seen.
- **Fixed:** A child that is already a zombie does not make the stop wait the full grace period. Process state Z, from `/proc/<pid>/stat` or from `ps`, counts as dead.
- **Fixed:** `clearUnverifiedApplies()` runs in a `finally` in the findings apply path, so a thrown re-run does not leave the spec tracked for a later signal.
- **Changed:** The network install check for the peer Playwright versions runs only when `QA_CORE_HEAL_PEER_INSTALL=1`. When it runs, it removes its cache folder afterwards.
- **Docs:** The README describes the default `testDir`, the total `--run-timeout` budget, and `npm install --legacy-peer-deps` for a Playwright prerelease. Code comments state the limit when both `/proc` and `ps` are missing: heal can signal only the direct child's process group. macOS always has `ps`.

It is passed to Playwright as `--config` and uses the same path rules as a findings `configPath`. `--config` is still the qa-core config file. The flag is listed in `--help`, in this README's flag table, and in `capabilities` (`features.playwrightConfig`).

- **Fixed:** SIGINT, SIGTERM, and `--run-timeout` kill the Playwright process group, including browsers that run in their own process group, and remove the `qa-core-heal-out-*` temporary output folder. Exit code 130 for SIGINT, 143 for SIGTERM. The stop sends SIGTERM, waits briefly so Chromium can delete its own temp folders, then sends SIGKILL. If `/proc` is missing, heal reads the process table with `ps` and still kills those groups. If the signal arrives during `--apply` verification, in spec mode or in findings mode, the spec is restored byte for byte and the audit log records `revertReason: "interrupted"`.

- **Fixed:** A findings `file` that is relative to Playwright's `testDir` is found when `project.configPath` is set and the file is not at the project root. The path still has to stay inside the project.
- **Fixed:** A redirect to `/` is treated as a login page, so SauceDemo prints the storage-state hint.
- **Fixed:** A proposal that removes or loosens an assertion is refused with `weakens-test` before any scratch copy is made.
- **Added:** Findings mode runs the changed test 3 times in the scratch copy by default. Every run must pass. `--shadow-runs <n>` overrides `heal.shadowRuns` in `qa-core.config.json`.
- **Changed:** Playwright (`playwright` and `@playwright/test`) is a peer dependency, `>=1.49.0`. This package was tested at 1.49.0 and at 1.64.1. The evals in this repo still run on 1.60.0.
- **Fixed:** The weakening guard also refuses a commented-out expect, an expect moved into a string, a removed `expect.soft` or `expect.poll`, and an added `test.skip`.
- **Changed:** `--verbose` prints one line when a findings `configPath` is ignored, and why. A spec that is a symbolic link inside the project is still refused with `spec-not-found`, and the message says Playwright lists the real file.
- **Changed:** `verification.baselineReproduced` stays true when the first run of the test already failed. This build does not run the unpatched test again inside the scratch copy. The schema text says the unpatched test failed in the shadow copy before the change. The field meaning in this build is the first run, which is the same value 0.4.0 wrote. The schema file is unchanged.
- **Docs:** The README says a SauceDemo session lasts only a short time, so save a fresh login to `.auth/state.json` before the heal run. It also notes that a hard link to a spec outside the project is not detected. The two findings sentences about `--dry-run` and `--test` sit with the paths paragraph.

## 0.4.0 (2026-10-27)

The first release of the findings and results contract (version 1) between qa-core-flaky and qa-core-heal. Everything in 0.3.x works as before. The new commands and flags are additions.

- **Added:** `--findings <heal-findings.json> --results <heal-results.json>`. qa-core-heal reads a findings file, runs only the one test each finding names, and writes one result per finding, in the same order. Proposals stay dry-run. Nothing is applied without `--apply`, and `--apply` still asks first unless you pass `--yes`.
- **Added:** `qa-core-heal capabilities --json`. It reports the tool version, the findings and results contract versions, the Playwright version, and which features this build has.
- **Added:** `--test <title>`. It runs and heals exactly one test of one spec file, in the first run and in the verify re-run. A title that matches more than one test is refused before anything runs.
- **Added:** `--run-timeout <seconds>`, which stops one Playwright run that takes too long. It works with `--findings` and `--test`. In findings mode the default is 10 minutes. A timed out finding is refused with the code `timeout`.
- **Added:** The handoff gate. A finding with the handoff `none` is refused with `ineligible-handoff` and no test is run for it. A finding with the handoff `suggest` is not run either. qa-core-heal also checks the verdict and the gates in the finding, so a real bug or an environment issue is never run as a locator problem.
- **Added:** A `proposed` result is only written when the change passes one run of the test in a scratch copy of your project. The scratch copy is deleted afterwards. If that run fails, the entry is refused with `verification-failed`.
- **Added:** An unknown findings `schemaVersion` exits with code 2 and a clear message. No results file is written.
- **Added:** The findings and results JSON Schemas are vendored in `schemas/` and shipped with the package. They are byte for byte the contract v1 files. A test checks their hashes.
- **Added:** Tests for the contract: schema validation of the results (ajv, as a dev dependency only), a fixture for each refusal code this build writes, a counted check that a targeted run executes exactly one test, and backward compatibility checks for the old flags.
- **Added:** `project.configPath` is passed to Playwright as `--config` for the test list, the first run, the scratch check and the re-run after an apply. A config in a folder below the project root now works. A missing config path or one outside the project is ignored and Playwright finds its own config.
- **Added:** The real location of each spec is checked against the project folder for every base folder, so a `..` in `project.configPath` or a symbolic link cannot bring in a spec from outside the project. Such a finding is refused with `spec-not-found`.
- **Added:** Every Playwright call in findings mode has its own temporary `--output` folder, so two runs at the same time in one project do not delete each other's traces.
- **Changed:** The README exit code table says that exit code 1 is also returned when an applied change was reverted. The README heading "License and Contributing" is in Title Case. The `--yes` text no longer calls `--accept-suggestions` a future flag. `skill/references/config.md` has no long dashes.
- **Changed:** `--version` now reads the version from one shared helper. The output is the same.
- **Not included:** Shadow verification with repeated runs (planned for 0.4.1) and the rule-based timing and selector fixes (planned for 0.4.2 and 0.4.3). The refusal codes `weakens-test`, `baseline-not-reproduced`, `ai-disabled` and `ai-invalid-output` are in the schema, but this build does not write them.

## 0.3.4 (2026-09-02)

A release built from a field-executed test round: fourteen structured cases run against the live playground pages surfaced two real defects, both fixed here, and retired two long-standing invalid sheet rows with markup evidence. A broken locator repeated inside one test now heals at every occurrence in a single consented heal (previously the lone stack-pointed line was healed, verification failed on the copy, and the correct heal was reverted). Emitted heals follow a new identity contract: the emitted locator is rebuilt from the confirmed element's own evidence, never from the broken locator's text: stable ids are preferred when the original was an id/css selector, name-carrying emits use the element's full computed value with exact: true, and a rebuilt emit that cannot be count-checked to exactly one match is never proposed. Refusals teach in two new definite cases (an icon-only control with no accessible name, an anchor without href that is not exposed as a link), the iframe note prioritizes same-origin frames over third-party widgets, and the revert summary line now reflects the non-locator classification its per-heal message already carried. Node 25's loader warnings are filtered at their thread of origin. The harness closes at 72/72 heals, 32/32 refusals, 10/10 intact across 16 suites (168 locators, 104 deliberately broken), 32 run-mode scenarios, 189 unit tests, and zero wrong heals.

**Three message-level fixes from the 0.3.3 transcripts.** (1) Nameless-candidate teaching: when a near-miss refusal's top candidate is DEFINITELY an icon-only interactive control with no accessible name (no text, no aria-label/labelledby, no title, no associated label, no value, all computed from the DOM read and never guessed), the refusal teaches instead of just scoring: `closest candidate #buttonGenerate is an icon-only button with no accessible name; a role-and-name locator cannot target it (add an aria-label, or target it by id)`; and when an unverifiable-kind refusal's candidate is an anchor WITHOUT href (definitely not exposed as a link, per ARIA), it appends `closest match is an anchor without href, which is not exposed as a link; target it by title or id, or give it an href`. The `#wipeAllButton` nameless-refusal pin is unchanged: it flows through a different branch (the parked-nameless gate, no closest candidate) and its button carries emoji text, so it is not icon-nameless; no other pinned refusal fixture contains either shape. (2) The iframe note prioritizes same-origin frames: cross-origin widget frames (the GitHub-Star shape, which can never hold the app's element) are omitted when same-origin frames exist, and reported count-only (`this page embeds N cross-origin widget iframe(s) …`) when they are all a page has; the /upload same-origin note is byte-identical. (3) The revert count line matches the per-heal classification: all-non-locator reverts say `N heal(s) reverted: the re-run still fails for a non-locator reason`, mixed reverts carry both counts, and all-locator reverts keep the original wording (scenario 24 byte-identical, scenario 30 pins the new summary). Pinned red-first: the icon-only near-miss, the no-href anchor refusal, and the mixed same+cross frames note naming only the same-origin src.

**Emitted identity is read from the confirmed element, never copied from the broken locator.** Field bug (/visibility): `page.locator("#removed")`, a truncation of `#removedButton`, healed to `getByRole("button", {"name":"removed"})`: the ladder resolved the button through Playwright's SUBSTRING name matching using the broken token, then emitted that token: green re-run, fragile locator (the real name is "Removed", the element has a stable id, the emit was neither; earlier sheet rows `{"name":"Hidde"}` and `{"name":"nam"}` are the same shape). New emit contract for every name-carrying ladder level (role/label/placeholder/text/title), aligning with the fuzzy path which already emitted full names: (1) a broken css original whose confirmed element carries a stable id (stable meaning NO generated segment; `#digest-checkbox-1f8a2e` rotates per deploy even though half of it is human), prefers the id heal (same locator family, strongest identity); (2) otherwise the element's own full computed value with `exact: true` (accessible name from aria-label / aria-labelledby / associated label / text / title / button value; getByLabel/getByTitle/getByPlaceholder/getByText gained exact emit forms); (3) neither readable → the bare-role emit, which the nameless gate refuses with its teaching message (a token-only heal is the less-identity violation in disguise). Every rebuilt emit is count-checked to exactly one, in the RESOLUTION's frame scope, so frame-resolved heals (`frameLocator(…).getByRole(…)`) rebuild correctly instead of falling to a false refusal, and a failed check falls through, never emitting a token. Kind guard, confirmation, and ambiguity rules unchanged. THE PIN SWEEP IS THE RELEASE NOTE: 24 pinned emits across unit tests and suites changed, every one strictly more specific (token names → stable ids: `#quantity`, `#quantity-field`, `#confirm-order`, `#do-register`, `#Email` on the live shop; token names → full names with exact: "Save preferences", "Weekly digest", "Update card" in its frame, "Help center", "Archive order", "Plan selector"; substring text/label emits → exact forms), every re-run green, zero pins became less specific and zero flipped to refusals (one early candidate flip, the frame-scoped update-card, was a scope bug in the count-check, found and fixed during the sweep, not accepted). One fixture changed by design: the rot page's button id gained a generated segment so the aria-label heal that scenario rot-tests is still the winning emit. Pinned fresh: the field css shape (`#removed` → `page.locator("#removedButton")`), the role variant (`{"name":"Removed","exact":true}`), and the nameless variant (class-only confirmable element → the nameless teaching refusal), plus the /textinput field shape (#newButtonNam → page.locator("#newButtonName"), replacing the token-name role emit from the transcript).

**A heal rewrites every identical occurrence within the failing test.** Field bug (full transcript): a test used the same broken literal twice inline: run-first matched the failing call from the stack, healed ONLY that occurrence, the verify re-run failed on the second still-broken copy, and the per-test revert undid the correct heal, leaving the file broken on every run. The revert contract behaved correctly; the heal scope was the defect. A matched heal now applies to EVERY structurally identical occurrence (same canonical method + args, the existing comparison) within the failing test's own body. The body span comes from the Playwright report's test declaration lines (a test's span ends where the next declaration in the file begins). It also includes the matched call's definition when it lives in a page object (a single definition, unchanged behavior). It is never wider: an identical literal in another test heals via THAT test's own failure in the same run, and passing tests' code is never touched. The scope is reported honestly: one heal, N occurrences (`healed to X (level=…, 2 occurrences in this test)`), the proposed-diff block and dry-run show every changed line, `--json` verdicts carry `occurrences: N` (additive), and consent invariance holds: the previewed plan lists all N edits and apply writes exactly those. A reverted heal is undone at every occurrence it rewrote. Pinned by run-mode scenarios: the field shape (red-first: one occurrence healed then reverted, file left broken; post-fix one heal, two edits, verify green, exit 0, zero broken copies, the near-identical-but-different literal beside them untouched) and the two-failing-tests twin (each heals via its own failure, no cross-test expansion); the POM single-definition scenario is unchanged, and no pinned diff output changed (single-occurrence formatting is byte-identical).

**Node 25: the hooks thread filters its own loader warnings.** Environmental, surfaced by the Node 23 → 25 upgrade and reproduced on the unchanged 0.3.3 build: Node 25 emits `ExperimentalWarning: stripTypeScriptTypes…` from the module-hooks THREAD, whose stderr relay can bypass or race the main thread's warning line filter, leaking loader noise into runs that must be warning-free. The hook itself now wraps its own thread's `process.emitWarning` with the same loader-noise families. Only our hook and Node's module machinery run on that thread, user code never does, so the conservative guarantee (user warnings always pass through) is untouched.

## 0.3.3 (2026-08-22)

The decoy release, driven by the team's third structured testing round against uitestingplayground. The headline: five field cases where a page's own text was an exact-match decoy for a broken locator (a heading literally named "Alerts", instruction paragraphs containing "Login") now heal to the real control, because kind-vetoed resolutions stash instead of terminating, the same structural fix 0.3.2 applied to confirmation mismatches, completed for the kind guard. Around it: revert messages now say when the heal was probably right and the test itself is the problem, refusals on pages with iframes explain that the element may live inside a frame the probe cannot scan, text composed across inline child elements is collected as one candidate, and shadow-DOM role healing is investigation-verified and pinned. Three of the round's filed findings turned out to be stale-build artifacts already fixed on 0.3.2, which produced a new process rule: sheet findings recorded on older builds are re-run on the current build before they count. The eval harness closes the release at 68/68 heals, 28/28 refusals, 10/10 intact locators kept across 16 suites (157 locators, 96 deliberately broken), 30 run-mode scenarios, and zero wrong heals.

**Text composed across inline children is one candidate.** Field case (/verifytext, reproduced on a byte-for-byte copy of the live page's markup): the greeting is authored as `Welcome <span>UserName</span>!`, so the full string "Welcome UserName!" exists on no leaf element, the pool held only the inner fragment, and a one-edit typo refused at 0.50 instead of scoring ~0.93. The text scan now lets a parent contribute its composed `textContent` as a single candidate when every child is a childless inline text-level element (span, b, i, em, strong, u, small, sub, sup, mark, abbr, time, wbr, br). Every contamination guard applies unchanged to the composed value: the 80-character cap keeps prose out, `code`/`pre`/`kbd`/`samp` are not in the allowlist so a parent containing code samples never composes, block containers and mixed structures still never aggregate, and no scoring, coverage, or NAME_ISH rule was touched. The field typo now heals to `page.getByText("Welcome UserName!", { exact: true })` (the exact form arriving via the existing substring-ambiguity fallback, since nested containers share the normalized text) with a green re-run proving the emitted locator resolves uniquely. Pinned red-first on the verbatim fixture, whose own code samples double as a live contamination guard; one sheet discrepancy reported honestly: the "Hello UserName!" decoy from the team's sheet no longer exists on the live page, and the decoy-never-wins property stays pinned on the modeled fixture that keeps it.

**Shadow-DOM role healing is verified and pinned, no live bug.** The sheet reported `getByRole('button', { name: 'Generate GUIDD' })` refusing "not found" on /shadowdom while a css selector healed into the same open shadow root. The investigation disproved all three suspected mechanisms directly: the shadow scan collects names and leaf text in the same per-root loop as ids and classes (the 0.2.1 contract holds in the code as written), accessible-name identities match into open roots empirically (the exact field mutation heals at 0.92 to the named role locator, an aria-label shadow button at 0.93, leaf text two roots deep at 0.92), and the route question was moot on one fixture. The field row was recorded on an older build, where the since-fixed terminal-verdict family could kill the run before fuzzy ever saw the shadow candidate. No source changes; the role-name typo heal into an open root is now regression-pinned end-to-end, with the healed click piercing the root as the proof.

**Refusals on framed pages say so.** Field root cause (uitestingplayground /upload): the page embeds its playground in an iframe, so the Upload button and file input live in a frame the top-document candidate scan never sees, and the refusals named only outer-page text with no explanation. The probe now records the iframes of each probed document, and not-found and below-threshold refusals on such pages append: "note: this page embeds N iframe(s) (src, ...) the probe does not scan; the element may live inside one. Frame-scoped locators cannot be healed - verify the locator inside its frame manually" (sources capped at 3, both scan and run modes). Frame-context healing stays out of scope by the emit doctrine, since it would require emitting chained frameLocator locators. Pages without iframes are byte-identical by construction, and the pin review confirmed zero existing refusal pins change: the two fixtures that already embed iframes pin heals only, so no pinned string gains the note.

**Revert messages classify why the re-run still failed.** Field case: the correct heal `#inputFeld` to `#inputField` was applied, the test's own assertion was independently wrong, the verify re-run failed, and the revert message implied the heal was bad. The revert contract is unchanged (still reverted, sources byte-identical, exit 1), but the re-run failure is now classified with the existing failure classifier: when it no longer fails for a locator reason, the message says "heal reverted: the re-run still fails, but no longer for a locator reason (failure line). The heal may be correct; the remaining failure looks like a test or app problem." A re-run still failing for a locator reason keeps today's message. Both the audit entry and the `--json` verdict carry `revertReason: "locator" | "non-locator"` (additive within schemaVersion 1). Pinned as run-mode scenario 30 (correct heal, wrong assertion: classified message, non-locator reason in audit and JSON, sources restored, exit 1), the counterpart to scenario 24's locator-reason branch, whose fixture was adjusted (an empty stray element removed) so it keeps testing the branch it was built for.

**Kind-vetoed resolutions stash, a kind tiebreaker resolves decoy bands, and content kinds are named.** Field-proven across five sheet cases (Alerts, Stopp, Login, Click mee, Dynamic IDs): documentation-style pages contain an exact-text decoy for the broken token (the page heading "Alerts" exactly matches the broken name), the decoy wins the intent ladder, fails the kind guard, and that verdict was terminal, so the fuzzy stage never ran and the real same-kind control one edit away was never proposed, the same structure the 0.3.2 stash fixed for confirmation mismatches. Three coordinated pieces, because the stash alone was not enough (with the veto stashed, the decoy re-enters the fuzzy band at 1.0 beside the real control and the band goes ambiguous): (1) a kind-vetoed intent-pass resolution is stashed, never terminal, with `roleCorrected` staying exempt; (2) a kind tiebreaker in the fuzzy band, deliberately a tiebreaker and not a pool pre-filter, applied only to multi-candidate bands after the exact-equality tiebreak, dropping candidates whose kind definitely conflicts with the original locator's declared expectation, so single-candidate verdicts and near-miss evidence are untouched (a pre-filter would have silently flipped the pinned `#export-button` kind-mismatch refusal into a generic not-found); (3) only a confirmed and kind-clean fuzzy heal outranks the stash, so every pre-fix refusal returns byte-identically where no valid alternative exists. The kind table also grew: `p`, `li`, and `span` are definite content kinds (refusals now say "candidate is paragraph" instead of "cannot be verified"), role attributes still win over tags, and `<a>` with href is a definite link while a no-href anchor stays unverifiable, which is ARIA-correct. Pinned by the new decoy-pages suite (heading, list-item, and paragraph decoys beside one-edit same-kind controls, red-first 0/5 then 5/5 at role level with green re-runs), with the kind-guard suite byte-identical and zero pin flips across all 16 suites.
